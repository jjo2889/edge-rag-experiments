# 게이트 결과 — 무맥락/정답근거 밴드 (2026-09-14, PC)

`docs/research_proposal.md` §4.5 의 기준선을 처음으로 실측했다. 결론부터:
**게이트가 열렸다.** 생성 층위를 접고 검색 층위로 축소하는 §8.2 경로는 타지
않아도 된다.

## 측정 조건

| | |
|---|---|
| 데이터 | SciFact test split 300문항 전체 |
| 조건 | `closed_book`(컨텍스트 없음) / `oracle`(qrels 문서 직접 주입, 최대 3개) |
| 모델 | Qwen3 dense Q4_K_M — 0.6B / 1.7B / 4B / 8B (`models/qwen3/MANIFEST.txt`) |
| 프롬프트 | 라벨 + JSON (`configs/prompt_system_scifact.txt`) |
| 환경 | PC, llama.cpp CUDA 빌드, `n_gpu_layers: 99` |
| 실행 | `SUFFIX=.pc OUT_ROOT=reports/gate-pc scripts/run_gate.sh` |

두 조건 모두 검색을 건너뛰므로 인덱스도 임베딩 모델도 관여하지 않는다. 미결로
남아 있는 임베딩 모델(§10.2)과 top_k(§10.3)와 무관하게 나온 값이다.

`판정가능`은 SUPPORTS/CONTRADICTS 188건이다. NOT_ENOUGH_INFO 112건은 근거를
줘도 정답이 그대로라 밴드를 37% 만큼 누른다(§6.5).

## 결과

```
칸         n      무맥락  oracle       밴드   │     무맥락  oracle       밴드
                 ──── 전체 300 ────         │      ── 판정가능 188 ──
────────────────────────────────────────────────────────────────────
0.6b    300   40.7%  60.3% +19.7%p   │  56.9%  52.7%  -4.3%p
1.7b    300   39.0%  69.7% +30.7%p   │  16.5%  62.8% +46.3%p
4b      300   37.0%  78.0% +41.0%p   │  10.1%  80.3% +70.2%p
8b      300   41.7%  78.7% +37.0%p   │  33.0%  82.4% +49.5%p
────────────────────────────────────────────────────────────────────
상수 분류기(항상 다수 라벨) = 41.3%
```

JSON 형식 준수율은 0.6B/1.7B/8B 100%, 4B 98.3%(5건 파싱 실패)였다.

## 읽는 법

**oracle 은 단조 증가한다.** 52.7 → 62.8 → 80.3 → 82.4. 크기가 커질수록 근거를
잘 읽는다. §4.1 이 요구한 용량-반응 관계가 그대로 나왔다. 다만 4B→8B 는 거의
평평해서(80.3 → 82.4) 이 과제에서는 4B 부근이 포화로 보인다.

**밴드는 4B 가 정점이다.** 무맥락 쪽이 단조가 아니기 때문이다.

무맥락(판정가능)이 `56.9 → 16.5 → 10.1 → 33.0` 으로 U 자를 그리는데, 양 끝의
높은 값은 성격이 다르다.

- **0.6B 의 56.9%** 는 실력이 아니다. 근거 없이 SUPPORTS 를 남발해 얻은
  점수이고, 그래서 근거를 주면 오히려 신중해지며 점수가 **떨어진다**(−4.3%p).
  밴드가 음수인 유일한 칸이다.
- **1.7B·4B 의 16.5 / 10.1%** 는 근거가 없을 때 "모르겠다"로 물러선 결과다.
  올바른 행동이고, 그래서 근거를 주면 밴드가 크게 벌어진다.
- **8B 의 33.0%** 는 근거 없이도 아는 것이 있다는 뜻이다. 생의학 지식일 수도
  있고 SciFact 학습 노출일 수도 있다 — 현재 데이터로는 구분되지 않는다.
  어느 쪽이든 밴드가 좁아지는 이유는 모델이 나빠서가 아니라 **바닥이 올라가서**다.

**oracle 만 봤으면 8B 를 골랐을 것이다.** §10.1 이 경계한 그 함정이 실측으로
나왔다 — 고르는 것은 "좋은 모델"이 아니라 "근거를 주면 답이 달라지는 모델"이다.
무맥락을 함께 재지 않으면 컨텍스트를 덜 쓰는 칸을 1등으로 뽑게 된다.

4B 의 조건별 예측 분포가 그 차이를 직접 보여준다.

```
무맥락   NOINFO 259 · SUPPORTS  32 · CONTRADICTS  9    판정가능 정확도 10.1%
oracle   NOINFO 108 · SUPPORTS 135 · CONTRADICTS 57    판정가능 정확도 80.3%
```

CONTRADICTS 가 9 → 57 건으로 늘었다. 부정 인식이 작동한다.

## 이 결과가 뒤집는 것

`docs/generation_quality_2026-08-02.md` 와 계획서 §9.2 의 "생성 모델 역량의 벽"
결론은 **상당 부분 프롬프트 문제였다.**

당시 판정 근거는 gemma-3-270m 위주였고, Qwen3-1.7B 는 부정문 쌍 3건(0/3)으로
탈락시켰다. n=3 이었고, 그때 프롬프트는 라벨을 나열하는 방식이라 §9.2 가
스스로 지적한 순서 편향에 그대로 노출돼 있었다. 라벨+JSON 으로 바꾸고 n=300
으로 재니 1.7B 가 46%p 밴드를 보인다.

**따라서 §9.2 는 "이 모델들은 근거를 읽지 못한다"가 아니라 "그 프롬프트에서는
읽지 못했다"로 다시 써야 한다.** 프롬프트 변경이 결과에 준 영향을 분리하려면
기존 문장형 프롬프트(`configs/prompt_system_scifact.sentence.txt`)로 같은 측정을
한 번 돌리면 된다. 그 대조가 이 전환을 결과로 만들어 준다.

## 계획서에 반영할 것

- **§9.2** — 프롬프트 의존성을 명시하고, 위 표를 추가한다.
- **§10.1** — 본 실험 생성기 후보를 **4B** 로 좁힌다. 1.7B 도 밴드가 열리므로
  비용 대비로 선택지에 남긴다(파이 기준 1.7B 18초 / 4B 30초대, §9.1).
- **§8.2** — 축소 경로를 타지 않게 됐다는 사실을 기록한다. 경로 자체는 남긴다.
- **§11** — 8B 의 무맥락 상승을 "데이터 오염 가능성" 위험 항목으로 추가한다.
  SciFact 는 2020년 공개 데이터셋이라 학습 노출을 배제할 수 없다.

## 환경 차이의 실측치 — §4.2 를 고쳐야 한다

계획서 §4.2 는 실행률·검색 지표를 "환경 불변"이라고 적었다. **엄밀히는
아니다.** 문항별로 대조하면 이렇다.

| 칸 | 판정 일치 | 답변 텍스트 동일 |
|---|---|---|
| 0.6b | 95.0% | 50.7% |
| 1.7b | 96.2% | 52.5% |
| 4b | 97.7% | 66.3% |

**개별 답변은 절반이 다르다.** llama.cpp 가 백엔드마다 부동소수점 누적 순서가
달라 로짓이 근소하게 갈리고, 그 지점에서 토큰이 뒤집히면 뒤가 통째로 달라진다.
같은 백엔드에서 두 번 돌리면 6/6 동일하므로 재현성 자체는 정상이다.

그런데 **판정은 95~98% 일치하고, 집계 지표의 차이는 최대 2.1%p 다.** §8.3 의
검출 한계가 짝지어 비교에서 5~9%p 이므로 **환경 차이는 검출 한계 아래**다.

정확한 서술은 "환경 불변"이 아니라 **"개별 출력은 절반이 다르지만 집계 지표의
차이는 검출 한계보다 작다(실측 ≤2.1%p)"** 다. 모델이 클수록 일치율이 오르는
것도 기록해 둘 만하다 — 판단이 확실해질수록 근소한 차이로 뒤집히는 경우가
줄어든다.

임베딩 쪽도 같은 성격의 차이가 있다. 같은 코퍼스로 만든 인덱스가 PC 와 파이에서
`chunks.jsonl` 은 바이트 단위로 일치하지만 `faiss.index` 는 벡터 원소의 94% 가
다르다. 절대차는 최대 1.6e-07 로 fp32 마지막 자리이고, 검색 순위의 근소한 동점만
갈릴 수 있다.
